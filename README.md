# menon.md

[![CI](https://github.com/rejeeshmenon/menon-md/actions/workflows/ci.yml/badge.svg)](https://github.com/rejeeshmenon/menon-md/actions/workflows/ci.yml)

Personal CV website for Rejeesh Menon, MD. Three jobs: a recruiter sees a credible academic CV, an LLM reading the URL gets clean structured facts, and visitors can ask a grounded chat about the CV that cannot invent credentials.

Live URL: https://menon.md

## How this was built

I am a hospitalist and clinical assistant professor, not a trained software engineer. This site, and the clinical software described on it, were built with Claude Code CLI and other AI coding agents. The AI writes code; the clinical logic, the architecture decisions, the safety boundaries, and the compliance calls are mine, and I can defend every one of them under questioning.

A few concrete decisions from this repo, as an example of what that means in practice, not a marketing claim:

- **Cloudflare Pages vs. Workers.** The build brief specified Pages. Mid-build, `@astrojs/cloudflare` turned out to have dropped Pages support in its current major version. Rather than pin to an old adapter to match the original spec, I moved to Workers with static assets, the adapter's current target, documented why in `docs/superpowers/specs/2026-09-21-menon-md-cv-site-design.md`, and kept the same free-tier cost and custom-domain flow.
- **A post-build fact-verification gate, not just a linter.** `scripts/verify-outputs.mjs` parses the actually-built HTML, JSON-LD, `llms.txt`, and `cv.json` after every build and asserts specific facts (citation count, license states, board-certification year) match `src/content/cv.yaml` byte for byte. This exists because a site whose whole premise is "every claim is verifiable" cannot rely on trusting that a template renders a variable correctly — it has to check the shipped output.
- **The chat's guardrails are enforced in code, not just in the prompt.** `src/chat/guards.ts` is pure, unit-tested logic (message-count limits, origin checks, a fail-closed rate limiter) that runs before the model is ever called, independent of whatever the system prompt says. A prompt is a request to the model; these checks are not.

Every architectural report referenced above, including two rounds of independent multi-agent design and content review, is committed in `docs/` rather than summarized after the fact — the commit history and those documents are the actual record of what was built and why, not a curated retelling.

## How it works

Every fact lives in one file, `src/content/cv.yaml`. At build time it is validated and rendered into every surface:

| Surface | Path | Generated by |
|---|---|---|
| Human CV page | `/` | `src/pages/index.astro` |
| Plain semantic HTML for ATS parsers and text browsers | `/plain` | `src/pages/plain.astro` |
| schema.org Person JSON-LD (in the head of `/`) | | `src/lib/jsonld.ts` |
| llms.txt index | `/llms.txt` | `src/pages/llms.txt.ts` |
| Full CV as markdown | `/llms-full.txt` | `src/lib/markdown.ts` via `src/pages/llms-full.txt.ts` |
| JSON Resume | `/cv.json` | `src/lib/jsonresume.ts` |
| Open Graph image, 1200x630 | `/og.png` | `scripts/og-image.mjs` (runs as `prebuild`) |
| Grounded chat page and floating widget | `/chat`, `/api/chat` | `src/pages/chat.astro`, `src/pages/api/chat.ts` |
| Personalized recruiter pages | `/for/<slug>` | `src/content/audiences/*.yaml` |

The markdown serializer in `src/lib/markdown.ts` is the single serializer for `/llms-full.txt`, the chat grounding context, and the section model behind `/plain`. Facts cannot drift between what humans read, what crawlers read, and what the chat asserts.

Everything is prerendered. The only server code is `POST /api/chat`, which runs in a Cloudflare Worker. The site works with JavaScript disabled, chat excepted: the floating button becomes a link to `/chat`, and `/chat` without JavaScript shows an email fallback.

## Stack

Astro 7, TypeScript strict, Tailwind CSS v4 (`@tailwindcss/vite`), `@astrojs/cloudflare`, Cloudflare Workers with static assets, Workers KV (rate limiting and chat logs only), Anthropic Messages API via `@anthropic-ai/sdk`, `sharp` for the OG image, `vitest`.

Note on hosting: the brief asked for Cloudflare Pages. The current Astro Cloudflare adapter no longer supports Pages, so the project deploys as a Worker with static assets. Same free tier, same custom-domain flow; only the commands differ (`wrangler deploy`, `wrangler secret put`).

## Editing the CV

1. Edit `src/content/cv.yaml`. Dates are ISO strings (`"2022"` or `"2022-10"`); omit `end` for present. Roles on projects must be one of `Designed and built`, `Built and shipped`, `Built and maintains`, `Led`, `Contributed`.
2. Run `npm run build`. The build fails if:
   - a required section or field is missing or has the wrong shape (`src/lib/cv.ts`),
   - the YAML contains an em dash, en dash or emoji (`src/lib/text.ts`),
   - any generated output disagrees with the YAML (`scripts/verify-outputs.mjs`),
   - built copy contains an em dash, en dash or emoji, or the main page exceeds its JavaScript budget (`scripts/scan-dist.mjs`).
3. Update `meta.lastUpdated` and, when Scholar changes, `research.metrics` and the matching stat tile.

Run `npm test` for the unit tests (loader, serializer, JSON-LD, chat guards, audiences).

## Adding an audience page

Create `src/content/audiences/<slug>.yaml`:

```yaml
slug: acme-health            # must match the file name; lowercase, digits, hyphens
company: Acme Health
role: Medical Director, Clinical AI
greeting: Prepared for the Acme Health clinical AI search
emphasize:                   # section ids, in the order to show first
  - clinical-ai
  - clinical-practice
bullets:                     # exactly three; each must restate a fact already in cv.yaml
  - ...
  - ...
  - ...
jdContext: >-
  A paragraph describing the role. The chat on this page reads it as context
  for "why is he a fit?" questions but never as a source of facts.
```

Section ids: `clinical-ai`, `clinical-practice`, `entrepreneurship`, `research`, `teaching`, `technical`, `education`, `honors`.

The page renders at `/for/<slug>` with `noindex, nofollow`, is excluded from the sitemap and blocked in `robots.txt`. Share the URL directly. The chat on that page posts the slug and the Worker appends the `jdContext` to the system prompt.

## Chat design

- Full-context grounding: the entire CV markdown is injected into the system prompt on every request. No vector database, no retrieval.
- The system prompt (`src/chat/prompt.ts`) requires: facts only from the CV, a `[Section name]` citation for every claim, a fixed refusal for anything not in the CV, third person, no persona changes, visitor input treated as untrusted data, no medical advice, under 200 words.
- Guards before the model (`src/chat/guards.ts`): JSON schema, 1,000 characters per message, 8 messages of history, alternating roles, same-origin check, 10 messages per hour per IP via `CHAT_KV`. If KV is unavailable the request is refused (fail closed, 429).
- Each Q&A pair is logged to `CHAT_KV` under `log:{timestamp}:{random}` with a 90-day TTL. The IP is stored only as a salted, daily-rotating SHA-256 prefix.
- Model comes from the `CHAT_MODEL` var (default `claude-haiku-4-5`). The key comes from the `ANTHROPIC_API_KEY` secret. Neither appears in the repo.

To review what visitors asked:

```bash
npx wrangler kv key list --binding CHAT_KV --prefix "log:" | head
npx wrangler kv key get --binding CHAT_KV "log:2026-09-21T10:05:00.000Z:1a2b3c4d"
```

## One-time setup

```bash
npm install

# 1. Create the KV namespace and paste its id into wrangler.jsonc (kv_namespaces[0].id)
npx wrangler kv namespace create CHAT_KV

# 2. Set the model API key as a secret (never a var, never in git)
npx wrangler secret put ANTHROPIC_API_KEY

# 3. Optional: a private salt for the IP hash (defaults to a fixed string)
npx wrangler secret put IP_HASH_SALT

# 4. Analytics: paste the Cloudflare Web Analytics token into src/lib/site.ts
```

## Deploying

```bash

```

The first deploy creates the Worker `menon-md` on `menon-md.<account>.workers.dev`. Then attach the domain (below). Every later deploy is the same command.

## Custom domain: menon.md

`.md` is Moldova's country-code TLD. Cloudflare Registrar does not support it, so registration stays at the current registrar (Regery or Netim tier, roughly USD 50 a year). DNS and hosting still move to Cloudflare:

1. In the Cloudflare dashboard, add `menon.md` as a new zone on the Free plan. Cloudflare assigns exactly two nameservers.
2. If DNSSEC is enabled at the registrar, disable it there first and wait for the DS record to clear (up to 24 hours). Switching nameservers with DNSSEC on breaks resolution.
3. At the registrar, replace the nameservers with the two Cloudflare-assigned ones. The `.md` registry accepts exactly two nameservers, which matches Cloudflare's default.
4. When the zone shows Active in Cloudflare, re-enable DNSSEC from the Cloudflare DNS settings (one click) and add the DS record it gives you at the registrar.
5. Attach the domain to the Worker: Workers & Pages, `menon-md`, Settings, Domains & Routes, Add, Custom domain, `menon.md`. Cloudflare creates the DNS record and the certificate. Add `www.menon.md` the same way if you want it, then a Bulk Redirect (or a redirect rule) from `www` to the apex.
6. Verify: `curl -I https://menon.md/` returns 200 and `curl https://menon.md/llms.txt` returns the index.

For a `.ai` domain the flow is the same, except Cloudflare Registrar does support `.ai`, so the domain can be registered or transferred there and the nameserver step disappears.

## Repository layout

```
src/content/cv.yaml           the only place facts live
src/content/audiences/        one YAML per recruiter page
src/lib/                      cv loader, markdown serializer, JSON-LD, JSON Resume, audiences, SEO helpers
src/chat/                     pure guard functions and the system prompt
src/pages/                    every route; api/chat.ts is the only non-prerendered one
src/components/, src/layouts/ Astro UI
src/styles/global.css         design tokens, base styles, print stylesheet
public/chat-widget.js         lazy-loaded chat UI (zero chat JS in the initial page)
scripts/                      og-image, verify-outputs, scan-dist
tests/                        vitest
docs/superpowers/             design spec and implementation plan
```
