## 3. The Surprise Layer

All five constraints (useful, credible, technically impressive, fast, understandable, not gimmicky) apply to every item below; each is justified against them individually.

1. **The Autonomy Boundary Diagram** (data visualization, real data only). A single static diagram, built from cv.yaml's own project bullets, showing exactly what each of the three software products lets AI/automation decide autonomously versus what requires physician sign-off (SuperHuman: guidance generation vs. physician review of every output; Priya: patient messaging vs. red-flag escalation to a human; Commerce: none, informational only). This is literally cv.yaml's own compliance language turned into a diagram instead of three separate paragraphs scattered across sections. Useful: answers the #1 question every clinical-AI hiring manager has. Credible: it's just his own stated facts, restructured. Technically impressive: shows systems thinking about AI governance, which is rarer than shipping code. Fast: static SVG, no runtime cost. Not gimmicky: it's not decoration, it replaces prose that currently exists and is harder to parse than the diagram would be.

2. **The CV-Grounded Chat, Made Legible Rather Than Novel** (AI, strictly CV-only). The product already plans a grounded chat (see `chat.starters` and `chat.fallback` in cv.yaml, referenced in DESIGN.md's ChatLauncher). The surprising move is not "add an AI chat" — every portfolio site has one now, and that alone is table stakes, not a surprise. The surprise is discipline: show the system prompt's grounding boundary in the UI itself (e.g., a visible one-line note "This answers only from the CV below — try asking something it doesn't know" with the documented fallback demonstrated live), so a technical evaluator can immediately test the guardrail rather than trust a marketing claim about it. This directly demonstrates the exact skill claimed in the SuperHuman bullets (owning "the safety rules for what generative output may say"), live, in front of the person deciding whether to hire him for that skill. Useful: lets a skeptical technical reader stress-test the honesty claim in five seconds. Credible: it is the claimed skill, demonstrated, not asserted. Technically impressive to this specific audience: a chat that visibly and provably refuses to hallucinate is more impressive to an AI safety hiring manager than a chat that answers everything. Fast: small grounded context, no vector DB needed given the CV's size. Not gimmicky: it degrades to a mailto link with JS off (per PRODUCT.md's own progressive-enhancement rule), and it is framed as evidence of a skill, not decoration.

3. **The Evidence Graph — product-to-citation-to-clinic mapping** (data visualization, real cv.yaml data only). A single interactive (or, if kept simple, static) map connecting: the 2014 Am J Physiol paper → enterade → Nestle license; the 2009 chikungunya RCT → UpToDate citation; the seven physical clinics → the specific software each one runs → the specific compliance decision governing that software. This is the "translational research to shipped product to governed deployment" throughline that currently takes reading four separate sections to reconstruct manually. Useful: this is the single fact pattern (bench-to-bedside-to-software) that makes this candidate unique among both physicians and engineers; making it visible in one view is worth more than any paragraph. Credible: every edge in the graph is a fact already in cv.yaml, nothing added. Technically impressive: demonstrates the same "structure scattered facts into a legible system" skill he'd bring to a clinical-AI data model. Fast: a static SVG/HTML diagram, no client JS required for the base version. Not gimmicky: it is not a force-directed graph for show — it should be a simple, readable flow diagram with three or four fixed lanes (Research → Product → Clinic → Compliance), which is the honest shape of the actual data, not an arbitrary "cool graph" imposed on it.

4. **A print-perfect two-page CV as a first-class, not degraded, output** (works with JavaScript entirely disabled, pure HTML/CSS). PRODUCT.md already commits to this ("It should print to a clean two-page CV") and DESIGN.md specifies print rules. The surprise is treating this as a *feature to show off*, not a fallback: a visible, permanent "Print / Save as PDF" affordance (not hidden in browser chrome) that produces a genuinely typeset two-page document — proper page breaks, no orphaned headers, real print stylesheet, not "the webpage minus some CSS." For an audience that will actually forward a PDF internally at Abridge/OpenAI/a hospital HR system, a beautifully print-typeset CV, produced by a pure `@media print` stylesheet with zero JavaScript, is a genuine "wait, personal sites don't do this" moment specifically because it demonstrates craft restraint rather than a framework flex. Useful: recruiters genuinely need a PDF to forward internally; this removes friction from the exact next step in the hiring funnel. Credible: it's literally the same content, restructured for a different medium, no separate truth to maintain. Technically impressive: correct print typography (widow/orphan control, running headers, page-break control) is unglamorous, hard to get right, and instantly recognizable to anyone who has fought a print stylesheet before. Fast: zero JS, pure CSS. Not gimmicky: it is the opposite of decoration — it is the single most utilitarian, boring-on-purpose feature on this list, which is exactly why it clears the bar for this specific brand ("verified, calm, exacting").

5. **Verification-in-place, not verification-by-promise** (interaction + credibility, no JS required for the base case). Every "Verify" link currently sends the visitor away from the site to an external state licensing board or ABIM lookup (correct and necessary — never fake this data). The surprise layer is a lightweight, honest affordance next to each verify link: a `<details>` element (pure HTML, no JS) that explains in one sentence what the visitor will find at that link and why it matters ("Washington Medical Commission: confirms active, unrestricted license as of [date]"), so a time-pressed recruiter doesn't have to leave the page and hunt through a government site's UI to confirm what they're looking for. Useful: shaves real friction off the exact verification behavior PRODUCT.md says defines success ("a recruiter can verify... in two clicks"). Credible: it never asserts the verification result itself, only what the external source will show, so it can't go stale or misrepresent. Technically impressive: near-zero, and that is correct — this is a craft/empathy signal, not a technology flex, and mixing technology flex into every single feature would itself be the tell of an AI-generated site. Not gimmicky: `<details>` is native, accessible, and print-hidden, matching DESIGN.md's "no motion, no decoration" register exactly.

## 5. What Everybody Else Would Do (and why to avoid it)

- **Gradient hero text on the name or headline.** A generic AI-assisted redesign reaches for this instinctively because it's the fastest way to make a hero "feel designed." It reads as SaaS marketing, is explicitly named in PRODUCT.md's anti-references, and undermines the "printed academic CV" register the brand is built on.
- **A hero photo with a soft-focus stock-style headshot treatment or an illustrated avatar.** The default move for "make it feel personal." For this specific brief, credentials and evidence carry more trust than a portrait; a photo (if used at all) should be small, plain, and secondary, never the hero's visual anchor.
- **Animated count-up stat tiles with icons.** Covered in Section 4 (#12) — the single most predictable "generic redesign" tell, and directly named as an anti-reference already.
- **A sticky "Hire Me" or "Let's Talk" CTA button following the scroll.** Standard SaaS/portfolio pattern; for a physician CV it reads as salesy and contradicts the "calm, understated" brand personality explicitly stated in PRODUCT.md.
- **Card-grid layout for every section with drop shadows and rounded corners at a uniform radius.** The default "make it look modern" instinct; DESIGN.md already correctly rejects shadows, gradients, and glass — a generic redesign would quietly reintroduce these under the banner of "polish."
- **A skills section rendered as animated progress bars or radar/spider charts ("Python: 90%").** Meaningless pseudo-quantification of an unquantifiable thing; actively damages technical credibility with an audience of engineers who will recognize it as content-free decoration.
- **Testimonial carousel or "what people say" quote section.** Nothing in cv.yaml supports invented quotes, and soliciting/fabricating them would violate the CV's own "no fact may appear on the site that is not written in cv.yaml" rule; a generic redesign reaches for social proof by default without checking whether the source of truth supports it.
- **Typewriter-effect text in the hero cycling through role titles ("Hospitalist. Founder. Builder.").** A very common "personal site with a twist" cliché; it is pure motion for its own sake, actively distracting for a compliance-minded CMO reader, and contradicts DESIGN.md's near-zero-motion rule.
- **Dark mode toggle switch in the nav.** DESIGN.md is explicit that dark mode should be a `prefers-color-scheme` response only, not a user-facing toggle; a generic redesign adds a toggle by default because "every site has one now," which is exactly the wrong reasoning here.
- **An "as seen on" or logo-wall section (WSU, university logos, journal logos).** Default credibility-signaling pattern borrowed from SaaS marketing; it substitutes logo recognition for actual verification, and this brief's stated success metric is "verify in two clicks," not "recognize a logo."
- **Confetti, cursor trails, or scroll-triggered reveal animations on every section entering the viewport.** The single most common "AI redesign trying to look expensive" tell; directly contradicts DESIGN.md's stated motion budget (nav underline + one widget fade, nothing else).

## 6. One Hero Direction (Agent 4's unconventional contribution)

**"The Boundary Line."**

Layout: keep the current hero's typographic content almost entirely as-is — name, headline, subheadline, address block, primary links — because PRODUCT.md's identity-front-loaded principle is correct and should not be sacrificed for novelty. The unconventional move is not visual, it is structural: split the hero into two columns on desktop (stacking on mobile, per the existing responsive discipline), text on the left exactly as today, and on the right a single, static, fully pre-rendered (no animation, no charts-library, inline SVG only) diagram: a horizontal line labeled "Patient" on the left end and "Generated output" on the right, with small fixed markers on the line for each real product from cv.yaml (SuperHuman, Priya/Clinic OS) showing exactly where the human-in-the-loop checkpoint sits between AI output and the patient — e.g., a marker reading "Physician sign-off" positioned before the line reaches "Patient" for SuperHuman, and a marker reading "Red-flag escalation" for Priya. Every label on the diagram is a direct quote or close paraphrase of a bullet already in cv.yaml (`Author of the clinical logic and the autonomy boundary`, `forbidden clinical topics and red-flag escalation rules`) — nothing invented, nothing decorative added.

Interaction: none required for correctness — it must render and communicate fully as static inline SVG with zero JavaScript, satisfying the "works with JS disabled" and "paper-first / print" principles simultaneously (it prints as a clean line diagram). The only optional enhancement, additive only, is that on hover/focus each marker reveals (via native `<title>`/`<details>`, no JS) the one-sentence compliance decision behind it, sourced verbatim from cv.yaml.

Why this clears the "genuinely valuable, not gimmick" bar: it does not decorate the hero, it replaces the single hardest-to-convey fact on the entire site (that this physician personally designs the human/AI boundary in live clinical software) with the one visual form that fact actually wants to take — a boundary line. It is the most unconventional of the five hero directions specifically because it puts a diagram, not a portrait or a bigger headline, at the visual center of the very first thing a visitor sees, which no CV site does — but it is defensible under every constraint in the brief: it is provably sourced from cv.yaml, it costs nothing at runtime, it survives print, it survives JS-off, and a Stanford professor or a CMO would read it as a serious clinical-governance artifact, not a design flourish.

## 8. Competitive Critique — What NOT to Copy

A lazy benchmarking pass against generic "best personal website" or "best developer portfolio" lists would import failure modes that are actively hostile to this brief:

- **Gradient hero text / gradient accent bars.** Ubiquitous on "best portfolio" showcases because it's cheap visual differentiation; on a physician CV it reads as consumer-app styling and immediately undercuts "verified, calm, exacting."
- **Animated counters ("0 → 223 citations").** Extremely common on portfolio and SaaS benchmarks; for citation counts specifically, animating a scholarly metric trivializes it — citation counts are a serious academic signal, not a KPI to dramatize.
- **Tilt-on-hover / 3D-parallax cards.** A staple of "creative developer portfolio" showcases; for project cards describing HIPAA-conscious clinical software, physical-feeling gimmicks read as tonally incongruous — nobody wants their BAA-boundary decision to wobble in 3D on mouseover.
- **Particle/canvas backgrounds (constellation dots, floating shapes).** Common in "impressive tech portfolio" lists; pure decoration, adds unnecessary paint cost, and reads as trying too hard, which contradicts the desired "this person doesn't need to perform" affect.
- **Typewriter/rotating-text effects in headlines.** Very common in "personal brand" site templates; motion for motion's sake, explicitly excluded by DESIGN.md's near-zero-motion rule, and it delays the reader from getting the actual headline.
- **Dark, "hacker terminal" aesthetics with monospace everything and neon accents.** Common in developer-portfolio benchmarks aiming for "technical" flavor; PRODUCT.md explicitly rejects this ("over-designed dark hacker themes"), correctly, because it reads as trying to look technical rather than being credible as a physician first.
- **Sticky floating social proof / logo walls.** Common on consultant and freelancer sites; borrowed credibility (a WSU logo, a journal logo) is weaker evidence than the "Verify" link pattern already in use here, and re-adding it would be a step backward in rigor.
- **A "philosophy" or "values" manifesto section with abstract statements ("I believe in evidence-based building").** Common on personal-brand sites; cv.yaml's single-source-of-truth discipline has no room for unfalsifiable values statements, and this exact audience (recruiters, professors, CMOs) is trained to discount them.
- **Overuse of scroll-triggered fade/slide-in reveals per section.** A default "make static content feel alive" move on every portfolio template; directly contradicts the stated design system's motion budget and adds nothing informational.

## 9. Final Design Thesis Contribution

- **Evidence over adjectives.** Every claim on the page should terminate in something checkable — a link, a number, a diagram, or a redacted artifact — never in a stronger verb.
- **Show the boundary, don't describe it.** Where the CV's real differentiator is a governance decision (what AI may do autonomously versus what requires a human), render it as a diagram of the actual boundary, not a paragraph about having one.
- **Nothing on screen that wouldn't survive being printed or read with JavaScript off.** If a feature can't degrade to legible static text, it doesn't belong on this specific CV, regardless of how well it demonstrates technical skill elsewhere.
- **Restraint is the flex.** For this specific audience, the absence of decoration is itself the strongest signal of technical maturity; every proposed feature must justify its existence against a physician CV's register, not against what looks impressive on a portfolio site.
